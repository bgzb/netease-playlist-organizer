# 网易云歌单整理

**0.1.0-preview.1 · 首个公开预览版**。在网易云 Mac 客户端中读取“我喜欢”，按曲风、BPM、语种、歌手筛选；预览并人工调整后，经明确确认写入一个目标歌单。原收藏保留，不删除或重排。

目前验证范围为同一台 Apple Silicon Mac、网易云 **3.1.1 / build 3019**。生产应用部署下限 macOS 13，尚未逐一验证所有 macOS 13+ 版本，也未验证第二台 Mac、Intel 或其他客户端版本。本项目与网易云无隶属关系。

## 安装与使用

从预览发布附件下载“网易云歌单整理应用.zip”，解压并将 `.app` 放入 Applications 或用户应用目录。普通使用不需要 Node.js、Python 或额外服务。应用采用 ad-hoc 签名，尚无 Apple 开发者签名与公证；首次打开按 [安装说明](docs/INSTALL.md) 操作。

1. 打开工具，从控制窗口打开整理面板。网易云若以普通方式运行，工具会请求确认重新打开，可能中断播放；取消即可保留当前客户端。
2. 在面板“重新读取完整收藏”并核对总数，再“开始 / 继续扫描”。可以暂停，恢复时重新校验账号和收藏；保存失败会提示，可重试或选择“仅本页继续”。
3. 选择条件：不同维度为 AND，同维度多选为 OR；BPM 包含边界。缺失数据单列为无法判断，无条件时须明确选择“全部收藏”。预览每页 50 首，可人工加入或移除。
4. 选择新建私密歌单或本人可写的已有歌单，点击“审阅写入清单”检查歌曲、目标与隐私，再确认写入。修改条件、选择、目标或账号会使确认失效。零结果不建空歌单。
5. 写入串行、每批最多 50 首，并读回核对；已有目标只添加缺少歌曲。结果不确定时先核对，恢复后重新审阅，不盲目重试创建。

## 缓存与隐私

扫描检查点、歌曲维度和写入恢复记录保存在网易云页面本机 `localStorage`，按账号隔离，键前缀 `ncm-organizer:v1:`。面板“清理工具扫描缓存”清除当前工具账号缓存，不删除歌单。确认状态不持久化。工具调用客户端已有能力；不要求粘贴密码或 Cookie，不提供独立上传服务。请勿在 issue 或日志附件中公开账号、歌曲清单、Cookie 或原始响应。

启动失败可能产生本机临时诊断文件 `ncm-organizer-v1-diagnostics/startup-failure.ndjson`，只记录固定错误类别、阶段和身份比较布尔值，不记录账号、歌曲、凭据、地址、PID 或原始错误；最大 16 KiB。可用 `getconf DARWIN_USER_TEMP_DIR` 找到临时目录，删除本工具日志即可重新收集。

## 退出、恢复与卸载

关闭控制窗口仍保留工具；再次打开显示同一个窗口。“移除面板”停止任务并移除入口。**移除面板或退出工具不会关闭网易云调试监听**：使用时客户端保留回环端口 19319。卸载或结束使用前，选择“恢复普通启动”并确认，工具让网易云正常退出并重新启动，关闭调试监听；可能中断播放。随后退出工具并删除 `.app`。工具不修改或重新签名网易云应用，不修改系统保护或注册开机启动。

## 已知限制与验证范围

- 曾出现一次冷启动断连而客户端稍后就绪，失败子条件尚未捕获；后续成功运行不能证明已经修复。可从控制窗口手动重试，工具不会持续自动重启客户端。
- 元数据可能缺失，客户端内部能力变化会使读取拒绝或暂停；网络、登录、权限或限流问题也会暂停扫描。
- 用户曾亲自测试写入流程；离线合成测试另外覆盖读回、去重和账号边界。这不代表所有账号、客户端版本或写入规模都已验收。
- 预览包使用现有图标，未公证；本机干净源码目录验证与 GitHub CI 配置均不代表第二台 Mac 或云端 CI 已通过。

## 源码与构建

MIT 许可见 [LICENSE](LICENSE)，开发依赖许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。构建支持 Node.js **24 LTS**（`.nvmrc`），Swift 6 工具链与 Apple Silicon Mac。锁定 TypeScript 7.0.2、esbuild 0.28.2、@types/node 20.19.0；运行原生测试需 macOS 14+ 及匹配 Testing.framework，生产应用仍以 macOS 13 为下限。

```bash
npm ci --cache ./work/npm-cache --registry=https://registry.npmjs.org
npm run verify:offline
bash scripts/swift-local.sh test --package-path launcher
npm run build:panel
bash scripts/build-app.sh
```

`verify:offline` 包含类型检查、合成 TS/JS 测试及重新构建的实际面板入口冒烟测试，原生测试使用合成传输和进程状态，不启动真实客户端。产物在 `work/dist/`；发布使用密封 ZIP，构建会解压检查签名、arm64 架构和面板内容。裸构建 `.app` 不作为额外发布入口。Swift 辅助脚本只在项目 `work/` 复制公开工具链接口，避免特定 CLT 接口不匹配，不修改系统工具链。

维护者只读探针 `npm run verify:read` 需要已由启动器连接的受支持客户端，不能用于打开调试监听；日常构建和 CI 不运行该命令。接口契约见 [runtime-contract](docs/runtime-contract.md)。
